## Findings

### Aggregate views

1. **Architecture delta — clean.** Every source file the epic added or changed imports only `core`, its own same-provider sibling, or node/libraries: `src/orch/sync.ts:1-2` (core only), `src/adapters/config/taxonomy.ts:1-8`, `src/adapters/gmail/GmailAdapter.ts:1-4`, `src/adapters/m365/M365Adapter.ts:1-3`. No core→adapter, adapter→cli, or orch→adapter import appears. `bun run build` (the `tsc` project-reference graph) and `bun run lint` (oxlint's AD-10 rule) are both green, and `package.json` is unchanged in the range — the epic added no dependency. **Disposition: accept.**
2. **God-class / size growth — none.** The epic's largest source file is `src/adapters/config/taxonomy.ts` at 268 lines. The two 400–500-line files in the tree (`src/adapters/gmail/GmailAuthAdapter.ts` 500, `src/adapters/m365/M365AuthAdapter.ts` 387) predate this epic. Largest single artifact is `tests/adapters/config/taxonomy.test.ts` (+535 net) — roughly twice its module — followed by `tests/adapters/gmail/gmail-adapter.test.ts` (+357). **Disposition: accept** (noted: the 4.1 suite is large for its module, but every case maps to a validation rule the module owns).
3. **Duplication map — measured, four re-implementations.** `readJsonObject` appears in four adapters (`gmail/GmailAdapter.ts`, `gmail/GmailAuthAdapter.ts`, `m365/M365Adapter.ts`, `m365/M365AuthAdapter.ts`); `isEnoent` in four (`config/configFile.ts`, `config/perAccountSettings.ts`, `config/taxonomy.ts`, `token/KeychainTokenStore.ts`); a fetch-shape declaration in three (both auth adapters plus `GmailAdapter`); `DEFAULT_CONFIG_DIR` in two (`config/configFile.ts`, `config/perAccountSettings.ts`); `AbortSignal.timeout(30_000)` in four. **Disposition: accept as-is** for the per-adapter `readJsonObject`/`isEnoent` — keeping each provider's adapter independent of its sibling's internals was an explicit design rule, and consolidating needs the shared adapter module the epic's Never lists excluded. **Defer** the fetch-shape consolidation, which now has a second consumer (see finding 4). Recorded so later retrospectives stop re-flagging it.
4. **Pattern divergence — the epic's own two sync adapters differ.** `M365Adapter` imports its fetch seam from its sibling (`src/adapters/m365/M365Adapter.ts:3`); `GmailAdapter` declares its own (`src/adapters/gmail/GmailAdapter.ts:43-53`). Both compile. The divergence is what makes the CLI's single injected `fetchFn` a cross-provider coupling that works only because the two `FetchResponseLike` interfaces are structurally identical (`src/cli/commands/sync-categories.ts:14,30,105,137`). Verified currently safe — the `body` widening of 4.2 is contravariantly safe and the shapes match member-for-member — but it is a latent compile break with no local signal. **Disposition: defer** (same consolidation item as finding 3).
5. **Spec-to-implementation reconciliation.**
   - (a) **4.3 frozen Boundaries: "`ensureCategories` also returns it"** (the per-account name→id map) is not implemented. `MailPort.ensureCategories` is `Promise<void>` (`src/core/ports/MailPort.ts:9`) and the in-session supervisor ruling gave the frozen core contract precedence; the map is reachable out of band via `GmailAdapter.labelIdsFor(accountId)`. Recorded in the spec's Implementation Notes. **Disposition: spec reconciliation, proposed** (the frozen block is frozen-after-approval; only the human edits it).
   - (b) **The epic context's "sync runs at startup regardless of mode" is not wired.** `src/orch/` holds only `sync.ts` and `src/cli` only the temporary commands; startup and dependency injection are Epic 11's by the context's own cross-story dependencies. **Disposition: accept as-is** (declared boundary, not a gap).
   - (c) **The architecture seed's `gmail-client.ts` (`googleapis` wrapper) was never built.** The epic used plain `fetch` per 3.1's decision; the seed file is still absent. **Disposition: accept as-is** (3.1's spec already records the wrapper as deferred; Epic 4 deliberately did not build it).
   - (d) **The 4.1 spec's own note:** the module-relative default `taxonomy.yaml` path resolves to the checkout root, which `tsc` does not copy into `dist/`. **Disposition: accept as-is** for a private, checkout-run CLI; a packaging decision when that changes.

### Lens findings (epic-wide diff, cross-story boundary weighting)

The three code lenses ran over the whole range diff (3826 lines). Findings consolidated across lenses; provenance kept.

- **Adversarial lens — 8 findings.**
  - A1 **(P1) A mistyped top-level `config.yaml` key silently ignores every override.** `configFileSchema` is a plain `z.object` (`src/adapters/config/configFile.ts:33-35`), so `taxonomyOverides:` parses, the unknown key is stripped, `readTaxonomyOverrides` returns `undefined`, and the defaults load with no error. This is the same typo class 4.1's own review patched at the *entry* level (`.strict()` on `overrideSchema`) — unguarded one level up where the user actually types. **Fix now.**
  - A2 **(P2) The `--account all` "no enabled accounts" hint fires when a listing threw, not when accounts are absent.** The listing catch increments `failures` but not `selected` (`src/cli/commands/sync-categories.ts:146-152`) while the gate reads only `selected === 0` (`:168`), so a real `ENOTDIR` error is followed by advice to create settings files. **Fix now.**
  - A3 **(P2) The Gmail label cache is a full-snapshot replace, so a future partial call silently drops ids.** `labelIdsByAccount.set(accountId, labelIds)` where `labelIds` holds only *this* call's labels (`src/adapters/gmail/GmailAdapter.ts:113-129`); the `CategorySyncTarget` seam documents no full-taxonomy precondition, and Epic 7's write-back depends on this cache. **Fix now** (document + pin, or merge into the prior snapshot).
  - A4 **(P2) `noAccountsHint` hardcodes the `~/.config/email-classify` display path while `configDir` is injectable** (`src/cli/commands/sync-categories.ts:77-85`) — the same class 4.1's review fixed for the taxonomy loader. **Fix now** (low).
  - A5 **(P2) A scalar `config.yaml` reports the misleading "`taxonomyOverrides` must be a list"** (`src/adapters/config/configFile.ts:59-63`), blaming a field when the file is not a mapping at all. **Fix now** (low).
  - A6 **(P2) A provider-listing failure is flat-counted with no per-provider summary line**, unlike the success path (`src/cli/commands/sync-categories.ts:144-159`), so failure reporting differs by failure mode. **Fix now** (low; fold into A2's fix).
  - A7 **(P2) Raw non-ENOENT `readdir` error text reaches the user** through the new CLI catch (`sync-categories.ts:144-149` over `config/perAccountSettings.ts:169`). **Defer** — already in `deferred-work.md` (2026-10-09) with the error-shape decision attached; this pass adds the measured fact that `--sync-categories` makes it user-reachable.
  - A8 **(P2) One `FetchLike` typed as M365's is injected into the Gmail adapter**, relying on structural identity of two distinct `FetchResponseLike` types. **Defer** (same consolidation item as findings 3/4).

The file schema must keep tolerating Epic 11's other keys, so the guard is a targeted unknown-`taxonomy*`-key check rather than `.strict()`. *Remediation, proposed.*

4. **Document and pin the Gmail label cache's full-taxonomy precondition** (or merge the snapshot into any prior one) so a future partial `ensureCategories` call cannot silently shrink the name→id map Epic 7 reads (`src/adapters/gmail/GmailAdapter.ts:113-129`). *Remediation, proposed.*
